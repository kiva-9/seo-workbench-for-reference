# 后台任务

入口为「系统管理 → 后台任务」（`#/background-tasks`），沿用当前网页登录身份，不需要配置 MCP token。AI Features 和原业务入口继续保留。

页面聚合四类持久记录：文章监控同步、AI 见解运行、业务后台操作、Google 资源目录同步。RSS 是 AI 行业资讯任务中的取源、解析与缓存步骤，在资讯任务详情展示来源结果、缓存和上次成功时间；没有独立 RSS 队列。普通业务修改回执不列作后台任务。等待式标题抓取、部分单篇/站外同步和定时维护尚未形成完整历史，本页不将其补写为后台记录。

列表支持任务类型、项目、谷歌账号、原始状态筛选、分页、手动刷新和活动任务跟踪。来源类型与原始 ID 共同标识记录，按创建时间、来源、ID 稳定排序。分页携带 `as_of`，固定新任务的可见上界；刷新建立新的分页快照，筛选和详情写入地址以支持返回、重载恢复。任务状态变化仍以最新记录为准。状态筛选内的任务完成后会退出该筛选。活动任务每 5 秒读取，页面隐藏时暂停；连续读取失败会提示恢复并停止自动跟踪。

列表、详情和操作分别在服务端鉴权。文章与 AI 按当前项目权限；业务操作要求创建者或管理员且仍覆盖该操作的全部项目；Google 目录同步按账号归属或管理员权限。先鉴权，再计数、排序和分页，入口位于系统管理不授予全局读取权限。详情只输出任务所需的字段，原始异常、租约、输入、凭据与模型提示不返回。

`queued`、`running`、`partial`、`failed`、`cancel_requested`、`cancelled`、`uncertain` 保留原意。未知总量只显示阶段及已处理数，不生成百分比。没有记录过的开始时间与耗时显示未知；迁移 `0022_background_task_observability.sql` 新增文章任务时间列，旧终态仅补可追溯的结束时间，新任务记录实际开始与结束。

重试与停止按每次读取时返回的 `canRetry` / `canCancel` 展示，提交时再次校验：

- AI 的 failed/partial/cancelled 复用既有 `retry_of` 幂等规则；uncertain 显示「结果/费用待核查」，不提供普通重试。
- 业务操作复用服务层的取消和重试能力及业务日期幂等键。停止只阻止未提交单元，不回滚成功结果。重试只选失败和未处理单元，并受配置、修订、保留期及数量上限约束。
- 文章任务与资源目录任务没有原任务取消/单元重试接口，详情提供返回业务入口重新提交；已有活动任务由原入口复用。

文章监控按钮按项目分别恢复服务端任务。提交回执前显示「正在提交」，202 后才显示已排队或执行中。切换项目和离开页面不会让旧轮询覆盖新项目；重载从服务端恢复。暂时读取失败有界退避，权限失效或任务不存在立即停止，提供重新读取进度；提交响应丢失时先读取服务端记录再允许重新提交。

网页文章同步一次提交就保存全部所选历史月份和文章修订，按每批最多六个月、45 次 Google 请求自动续排。项目范围过大时自动拆分文章，预算不会使任务提前结束或要求用户反复点击。当前批完成后保存剩余范围，再进入下一批；本月在每组历史处理结束时更新，所有组完整成功后才写文章成功时间。历史来源不可用仍保留未知值。执行期间可查看已完成月份、批次数和待处理范围。真实来源失败或权限、配置、文章修订变化会停止并保留成功事实及未完成范围，核查后可从业务入口重新提交。

迁移 `0023_article_sync_queue.sql` 保存队列检查点、下次执行时间和执行租约。服务重启后自动认领未完成任务，读取接口不推进任务；过期执行者不能写入指标或检查点。部署维护 HOLD 期间不消费队列。迁移前的终态任务仅保留历史记录，不自动重放；没有检查点的旧活动任务仍在心跳过期后记失败。
