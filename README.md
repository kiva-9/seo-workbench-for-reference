# SEO Workbench · 文案工作台

一个面向个人与小团队的 **SEO 业务管理系统**：管理多个 SEO 项目的文章、任务、排期与常用链接，并按项目登记的 URL 从 **Google Search Console（GSC）** 和 **Google Analytics 4（GA4）** 抓取表现数据，在同一个界面里完成「登记 → 抓取 → 看板 → 复盘」的闭环。

> 本仓库是内部系统的**公开参考版本**，供其他业务的同事了解产品设计与实现思路。已移除内部部署、CI/CD、开发工作流配置与测试套件，不含任何真实业务数据；业务代码与数据库迁移保持原样。

## 解决什么问题

SEO 代运营业务的日常是「**多项目 × 多谷歌账号 × 按月指标**」的矩阵：每个客户一个项目，项目分布在不同的谷歌账号下，效果要看每个月每个 URL 的点击、曝光、排名与转化。在表格里维护这套数据有几个反复出现的痛点：

- **数据靠手工搬运**：GSC / GA4 后台看一次容易，留下按月、按 URL 的历史记录很难；GA4 一过保留期老数据就没了。
- **账号口径不齐**：不同项目的站点和资源分属不同谷歌账号，切换登录抓数容易抓错、抓漏。
- **业务对象零散**：文章、任务、排期、外链、达标口径分散在不同工具里，复盘时对不上。
- **失败与缺失不可区分**：手工记录里「没抓到」和「真的是 0」长期混在一起，达标判断失真。

本系统把这些收进一个自托管的 Web 应用：数据落在本地一个 SQLite 文件里，抓取按账号授权隔离，每个数字都带着成功/失败/未知的事实记录。

## 功能模块

| 模块 | 说明 |
| --- | --- |
| 任务管理 | 已逾期 / 待办 / 已完成看板与月视图日历，拖拽改状态；「已逾期」由「到期日 < 今天且未完成」自动派生 |
| 项目管理 | 项目名称与域名；全员浏览和认领资源候选；GSC 与 GA4 **各自独立**绑定谷歌账号 + 站点/资源 |
| 项目文章管理 | 单个项目的文章列表（URL + 标题 / 关键词 / 发布日期）、任务、链接与外链概况 |
| 文章监控 | 原数据抓取、绩效看板与外文数据合并后的统一监控页：GSC 按自然月、GA4 本地累计到今天；月度明细、达标列、XLSX 导出 |
| 链接库 | 各平台散落的链接挂到项目下或放进个人收藏，标签过滤 + 搜索 |
| AI 见解 | 跨项目看板：文章表现、行业资讯、收录监控三类结果，规则事实 + 可选的大模型解读 |
| Agent 接入 | 「MCP 管理」中创建、重置和撤销个人 Token；「工具使用指南」搜索同一后端的 48 项 MCP 工具与示例 |
| AI 功能配置 | 管理员维护模型条目（Base URL / 密钥加密保存 / 主备模型），项目成员维护关注词与调用限制 |
| 谷歌账号 | 多账号 OAuth 授权；断开账号时自动解绑引用它的项目 |
| 项目候选 | 从已连接账号的 GSC / GA4 目录自动发现网站，一键认领建项目并绑定数据源 |
| 后台任务 | 文章同步、AI 运行、资源目录同步等长任务的统一入口：状态、进度、重试与停止 |
| 设置 | 登录账号管理、Google Cloud 客户端 ID / 密钥 |

界面提供三套配色与明暗两种模式，选择保存在浏览器本地。字体栈优先 Google Sans / MiSans；参考版未随附字体文件，页面自动回退系统字体。

## 页面组织

前端没有框架和构建步骤，页面与侧边栏一一对应，每个页面一个文件（`public/js/pages/`）：

| 侧边栏分组 | 页面 | hash 路由 |
| --- | --- | --- |
| 工作空间 | 任务管理（看板 + 日历）、项目管理、链接库、文章监控 | `#/task-management` `#/projects` `#/docs` `#/article-monitor` |
| 工作空间 | 项目文章管理（项目详情） | `#/project/:id` |
| AI Features | AI 见解、Agent 接入、AI 功能配置 | `#/ai-insights` `#/mcp` `#/ai-settings` |
| 系统管理 | 谷歌账号、项目候选、设置、后台任务 | `#/accounts` `#/project-candidates` `#/settings` `#/background-tasks` |

早年的「数据抓取 / 绩效看板 / 外文数据」三个页面已合并进文章监控，旧 hash 会重定向。跨页面共用的交互（资源选择器、筛选组合框、AI 卡片等）放在 `public/js/components/`，一个组件一个文件。

## 技术架构

```
浏览器                        Node.js 服务端（单一进程）
┌────────────────┐   HTTP    ┌─────────────────────────────────────┐
│ 原生 ES Modules │ ───────► │ Express                              │
│ hash 路由 + 手写 │           │  middleware：Host/Origin 校验 →      │
│ CSS，无构建     │           │    Cloudflare Access 验签 → 当前用户  │
└────────────────┘           │  routes/：一个业务一个路由文件         │
                             │  services/：业务流程与长任务           │
                             │  db/：扁平查询对象（每表一文件）        │
                             │  google/：OAuth + GSC/GA4 抓取         │
                             │  insights/：AI 见解三模块               │
                             │  mcp/：把同一后端开放给 AI 代理          │
                             │  lib/：纯函数（日期、URL、并发…）        │
                             └──────────────┬──────────────────────┘
                                            │ node:sqlite
                                     SQLite 单文件 + 自动备份
```

- **运行时与依赖**：Node.js 24（数据库用内置 `node:sqlite`，Google API 用内置 `fetch` 直连 GSC v3 与 GA4 Data API v1beta）。运行时依赖只有 4 个：Express、官方 MCP SDK、Zod、rss-parser。
- **后端分层**：`routes/` 只做参数与权限；业务流程在 `services/`；SQL 全部写在 `src/db/queries/` 里用 `db.prepare()` 执行，一张表（一个业务）一个文件，由 `src/db/api.js` 合并成一个扁平查询对象并在合并时查重名。
- **数据库迁移**：结构变化都是 `migrations/NNNN_名称.sql` 编号文件，启动时由迁移执行器（`src/db/migrate.js`）按编号应用、记入 `_migrations` 表，失败整体回滚。
- **前端**：原生 ES Modules + 手写 CSS，`public/js/app.js` 维护 hash 路由表；`theme.css` 是唯一的色彩 / 字阶 / 间距来源，由 `npm run theme`（`scripts/gen-theme.mjs`）生成。
- **认证双模式**：同一套代码，不配环境变量就是本机单用户模式；配上 Cloudflare Access 团队域名后自动切换为团队模式（身份来自 Access JWT 验签，项目按人隔离，管理员可转让项目、加协作者）。
- **MCP**：`/mcp` 用个人 Token（PAT）走无状态 Streamable HTTP，与网页共用同一套权限和业务服务；`MCP_PHASE` 按阶段控制工具开放范围。

## 值得借鉴的实现思路

1. **零构建全栈**。前端原生 ESM、后端 CommonJS，没有打包器、没有 ORM、没有额外数据库。个人 / 小团队工具的维护成本主要在依赖和构建链上，这套选型让「clone 下来 `npm start` 就能跑」长期成立。
2. **配置只进环境变量**。`src/config.js` 是唯一配置入口，全部来自环境变量且都有安全默认值；不设任何变量即单用户本机模式。安全边界类的配置（团队身份、外部调用开关）刻意不走网页设置，避免用配置接口扩大权限。
3. **编号 SQL 迁移 + 失败整体回滚**。迁移就是纯 SQL 文件，执行器只做三件事：按编号排序、记账、包事务。编号不连续或重复直接报错，已发布的迁移文件永不修改。见 `src/db/migrate.js`。
4. **每表一文件的扁平查询层**。`db/queries/*.js` 工厂注入数据库后端，`api.js` 合并成 `db.projects.list()` 这样的扁平对象，重名直接报错。没有 ORM 的抽象成本，但 SQL 仍有单一归口。
5. **多账号 OAuth 令牌按邮箱隔离**。一个 Google Cloud 项目 + 测试用户白名单承载任意多个谷歌账号；令牌按账号各存一份，抓取时用对应账号的令牌，只能读到该账号有权限的站点。断开账号自动解绑引用它的项目，不留悬空引用。
6. **抓取数据口径先行**。GSC 按自然月取定稿数据（Google 只保留 16 个月），GA4 走「本地累计账本」——每次只把上次累计之后的新数据加进本地，过保留期被 Google 删掉的老数据本地仍在，重复抓取不重复累加。**失败不写成 0**：每个来源的成功/失败事实独立保存，未知就是未知，和真实零值严格区分。
7. **持久化同步队列**。一次历史同步自动按「每批最多 6 个月、45 次请求」分批，剩余范围持久化排队，服务重启后自动认领继续；执行租约 + 检查点保证过期执行者不能写入。见 `migrations/0023_article_sync_queue.sql` 与 `src/services/article-sync-queue.js`。
8. **后台任务可观测**。所有长任务（同步、AI 运行、导出、目录刷新）落库并在「后台任务」页统一呈现：状态机明确（queued / running / partial / failed / uncertain…），`uncertain` 单独表达「结果或费用待核查」，不伪装成成功或失败。
9. **同一后端开放给 AI 代理**。MCP 层不复制业务逻辑，直接复用 services 层；写入带修订号、CAS 与幂等回执，读取轮询不触发抓取。工具按能力分阶段开放，个人 Token 与网页登录并行、权限实时校验。
10. **AI 输出的事实约束**。大模型只收到确定性生成的定性事实（方向、区间、限制），不接触原始数值；输出经结构、引用、数字符号校验，被拒内容不落库；费用走「先原子预留、后记账」的预算账本，未知费用保留 `null` 不当零。见 `docs/ai-insights-contract.md`。
11. **零依赖测试**。内部仓库用 Node 自带的 `node:test` 覆盖迁移、权限、同步口径、MCP 协议与前端交付：每个测试用 `SPM_DATA_DIR` 指向一次性临时目录，绝不碰真实数据；外部调用一律 mock `global.fetch`；冒烟测试真起一个服务把接口挨个请求一遍。参考版未随附这套测试，但「测试零依赖 + 数据目录隔离 + 全 mock 外部调用」是它敢随手改的结构性原因。
12. **生成式主题**。三套配色由脚本从色板生成唯一的 `theme.css`——色彩、字阶、间距、圆角只有这一个来源，改主题不改组件样式。内部版本同时自托管 MiSans / Google Sans 官方分片（来源与 SHA-256 记录在清单里）；参考版未包含字体二进制，CSS 字体栈自动回退系统字体。

## 本地运行

需要 **Node.js 24**（`node --version` 核对）：

```bash
npm install
npm start          # http://localhost:8477
npm run dev        # node --watch，改代码自动重启
```

也可以双击 `start.command`（macOS）或 `start.bat`（Windows）。所有环境变量都可以不设，默认即本机单用户模式，数据在 `./data/`（不进 Git）。

### 连接 Google 数据（可选）

系统只在配置了 Google 数据源后才有抓取能力，流程约 20 分钟，全程只需一个主账号建 Google Cloud 项目：

1. Google Cloud 新建项目，启用 **Search Console API** 和 **Analytics Data API**；
2. OAuth 同意屏幕选 External / Testing，把所有要连接的谷歌账号加进测试用户；
3. 创建 OAuth 客户端（Web 应用），回调地址填 `http://localhost:8477/oauth/callback`；
4. 系统内「设置」粘贴客户端 ID / 密钥，再到「谷歌账号」逐个连接并授权；
5. 项目里分别选择 GSC 与 GA4 数据源（可以是不同账号），即可按月抓取。

账号只能读到自己在 GSC / GA4 里有权限的站点和资源；数据口径的细节见 [文章监控口径](docs/article-monitor.md)。

### 环境变量

见 [.env.example](.env.example)。常用：`PORT`（默认 8477）、`SPM_DATA_DIR`（数据目录）、`PUBLIC_HOST` + `CF_ACCESS_TEAM_DOMAIN` / `CF_ACCESS_AUD`（反向代理 + 团队模式）、`MCP_ENABLED` / `MCP_PHASE`（MCP 开关与阶段）、`AI_*`（AI 见解与模型配置，默认关闭外部调用）。
