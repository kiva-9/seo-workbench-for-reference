# 文章监控的数据口径

文章发布日期是业务起点。发布当月从发布日期开始计算应覆盖的区间，之后的历史月份按自然月计算，本月按每个来源的最新可用日期保存临时数据。没有发布日期的文章不取数，并提示补填，不使用登记日期、创建日期或项目手填起点替代。GSC、GA4 浏览与关键事件的实际成功覆盖独立保存；历史来源不可用时仍为未知或历史覆盖不完整，不能记为真实零。首次回填沿用现有同步入口，不新增月份选择。网页同步一次提交完整历史范围，已完成来源跳过网络取数，预算按每批最多六个月、45 次请求执行；剩余月份持久化排队并自动继续，项目过大时自动拆分文章，无需反复点击。明确指定超过六个月也会自动分批。底层等待式引擎保留单批范围限制，网页队列负责完整范围的调度。

每个月的每个来源只贡献一份有效值。正式月度值完成定稿和安全窗口后接管；此前可使用该月临时值，失败重试保留最后成功事实。列表、月度明细和 XLSX 月度矩阵使用同一来源选择函数，不能把失败时保留的正式值与同月临时值相加。历史完整月和错误月各按月份计算一次；本月三项指标不会增加历史完整月数。

MCP 默认站内同步保留发布日期以来的完整计划，按实际待执行的持久单元及检查点预算排队，已完成历史不占执行单元。显式指定月份和站外同步保留既有范围校验；持久队列的 200 单元和检查点预算继续适用。

转化率仅使用同配置、同覆盖区间且浏览和事件均已知的配对。没有可比配对时为 `null`，真实测量到零事件时可以是 0%。汇总同时提供纳入与排除文章数，不把未知事件项目的浏览加入分母。点击 20、浏览 50、转化率 1% 的 OR 达标阈值和 30 天观察期保持不变；缺发布日期时待补填，不能判定观察期。

本月 GSC 使用 `dataState=all`，与探测的新鲜日期一致，仍明确标为未定稿临时数据；历史月使用定稿数据。跨 URL 批次先合并完整响应，再按文章的当前与曾用地址归集一次。截断或任一批次失败不会更新该来源的成功事实。GA4 日期维度在适配器边界统一为 `YYYY-MM-DD`。同步任务保留引擎状态、未执行原因和范围拆分提示，不把未配置或超限当成功。

月度明细集中显示点击、浏览、曝光、CTR、排名和关键事件，并保留来源截止日、完整性及曾用地址；不再提供旧诊断区域或旧 GA4 迁移基线功能。旧基线读写和导出入口、手填监控起点入口及旧迁移预检脚本已退役。已发布的历史迁移和原有存储保留，以保证完整初始化与升级，不执行数据删除，也不提供旧功能兼容路径。当前月度数据、临时数据、Google 连接器及 URL 历史继续使用。

迁移 `0020_article_current_gsc_detail.sql` 仅新增临时 GSC 曝光、CTR、排名及成功明细字段；升级已有数值保持不变，旧记录没有可追溯的辅助指标时仍显示未知。代码修复不会自动回填历史错误零值或重算已冻结的站外区间，这些操作需要另行核定范围。

参考：[Search Analytics 请求合同](https://developers.google.com/webmaster-tools/v1/searchanalytics/query)、[GA4 日期维度](https://developers.google.com/analytics/devguides/reporting/data/v1/api-schema)。

迁移 `0021_article_publication_fetch_guard.sql` 在发布日期实际改变时统一推进取数修订并标记待刷新，覆盖 HTTP、MCP 与导入；相同日期、标题和署名变更不触发。旧范围的迟到月度与临时写入被守卫拒绝，不在升级时修改已有记录。

文章级成功收敛在同一守卫写入中维护 `metrics_dirty=0` 与 `last_synced_at`，web 与 MCP 共用此完成语义。剩余月份、失败、缺发布日期和修订/配置变化不会被按钮恢复清除。达标列仅在存在真实活动同步时显示「同步中」；待刷新与来源失败不证明后台仍在执行。顶部「数据异常」使用达标状态 `data-issue` 计数，与点击筛选、行状态及导出一致；独立来源异常计数不冒充该筛选。任务结果与剩余月份可在[后台任务](background-tasks.md)查看。
